# 文本与讲解审查：pandas_finance_to_analysis.ipynb

## 审查范围

只审查 markdown cell 的文本与讲解质量，不涉及代码 cell 和整体章节结构（结构问题已在上轮讨论并修正）。

---

## 一、核心判断

新版在数据主线和阶段划分上已经理顺——两张表的分离、脏表预置、阶段 8 回归公司面板数据，这些改动方向都是对的。但文本层面存在系统性的干燥问题：**大部分 markdown cell 的功能偏向"信息传递"，缺少"经验传递"**。读起来像 API 速查手册，不像一个有教师在场的讲义。

---

## 二、概念单元几乎全是"编号列表 + 函数签名"模式

这是最直观的干燥来源。随机抽取几个概念 cell：

**Cell 8（读取数据）：**
> 1. `pd.read_excel("文件路径")`：读取 Excel 文件，得到一张 `DataFrame`。
> 2. `head()` / `tail()`：分别查看开头和末尾，默认显示 5 行

**Cell 28（iloc/loc）：**
> 1. `.iloc[行位置, 列位置]`：按整数位置选择。
> 2. `.iloc` 切片：写法和列表切片类似
> 3. `.loc[行标签, 列标签]`：按标签选择。
> 4. `.loc` 标签切片：按标签切片时包含结束点，这和 Python 列表切片不同。

**Cell 95（groupby）：**
> 1. `groupby("分组列")`：按照某一列把数据分组。
> 2. `.agg(新列名=("被计算列", "统计方法"))`：对每组计算统计量

几乎每个概念单元都采用这个模式。优点是清晰、可查；缺点是"没有人"——读者看到的是函数说明书，不是老师在说话。

对比旧版处理同类知识点的写法：

> "我们首先观察到：股票代码不对，如平安银行的代码应该是 000001。读取时默认把股票代码列识别为数字 int64，因此前面的 0 就被去掉了。"

> "注意：pandas 中，大部分'写'操作，默认都'不会改变原值'：你会获得一个包括修改后的新数据的 DataFrame。"

> "问：这一列是否有 NA，或者有多少个？对上述结果求和即可！True 会被视为 1，False 被视为 0"

旧版是**对话式**——有观察、有提醒、有追问。新版是**陈述式**——只交代函数名和功能。这是"干燥感"最直接的来源。

## 三、缺少"如果……会怎样"的经验细节

知识本身篇幅很短，一眼就能看懂；但细节——那些碰很多钉子才能领悟的东西——篇幅往往很长。新版系统性地缺失了这一层。每个函数只说了它"做什么"，没有说它：

- 哪里容易做错
- 做错了会怎样（报什么错、出什么怪结果）
- 怎么发现做错了
- 怎么绕开

具体缺口（只列典型，不全）：

| 位置 | 当前表述 | 缺失的细节 |
|------|---------|-----------|
| Cell 28（loc 切片） | "按标签切片时包含结束点，和 Python 列表切片不同" | 说了结论，但没说当 index 恰好也是整数时，loc 和 iloc 的行为差异会让学生困惑——这是真实高频踩坑点 |
| Cell 32（复合条件） | "每个条件外面都要加括号" | 说了规则，但没说忘了加括号时 pandas 报什么错，以及那条错为什么新手看不懂 |
| Cell 58（读脏数据） | "数字列如果显示为 object，常常说明里面混入了文本" | 这是一个好细节。但缺了下半句：混入了什么文本、怎么快速定位是哪一行——`pd.to_numeric(errors="coerce")` 之后看 `isna()` 新增了哪些行 |
| Cell 85（merge） | "通常检查合并前后行数" | 说了要检查，但没说行数变多了意味着什么（右表有重复键）、行数变少了意味着什么（匹配不上）、以及怎么排查重复键 |
| Cell 103（transform） | "agg() 通常得到每组一行，transform() 得到和原表等长的一列" | 这是正确的技术描述。但没回答学生最可能困惑的问题：什么时候用 agg 什么时候用 transform？一个具体判断标准是"如果下一步还要和原表一起用，用 transform" |

旧版在这方面的密度很高——链式赋值演示了三种情况（成功、失败有警告、失败无警告），`dropna()` 解释了为什么 DataFrame 比 Series 复杂，`fillna` 前值填充提示了"第一个值就是 NA 就无法填充"。这些内容在新版中基本被精简掉了。

## 四、阶段之间缺少衔接

每个阶段的开头都有独立的动机说明，结尾都有小结。但两者之间没有桥：

- 阶段 3 小结："我们得到了 `annual_2020_rank`"
- 阶段 4 开头："真实数据进入统计和合并前……读入一张待清洗的财务指标表"

读者刚和 `annual_2020_rank` 建立了熟悉感，它就被默默地抛弃了。如果加一句"这张排名表先放在这里，等我们把另一张表洗干净，两张表会在阶段 5 碰面"，叙事线索就不会断。

类似问题存在于每一对相邻阶段之间——每阶段读起来像一篇独立短文，而非一章的连续章节。

---

## 五、"范例"的质感不统一

阶段 1–3 的范例非常具体，有明确的筛选目标和产出物：

> "选出 2020 年、行业名称包含'制造'、净利润为正、营业收入不缺失、资产负债率低于 0.7 的公司年度记录"

阶段 4 的范例变抽象了：

> "把证券代码、日期、收益率、每股收益和利润指标整理成可计算、可合并的格式"

阶段 6 恢复了一些，阶段 7/8 又弱下去。范例越具体，学生越知道"我做这个是为了什么"；范例越抽象，越像"为了练这个函数而练这个函数"。

---

## 六、几个写得好的地方（值得保留和扩展）

这些段落在整章中很突出，因为它们有"教师的声音"：

- **Cell 0**："读入后看一眼，筛选后看一眼，生成新列后再看一眼"——整章最好的句子，建立了条件反射式的习惯。这个"看一眼"的 motif 如果在后续每个阶段小结中被呼应，会变成一条贯穿的红线。

- **Cell 129（阶段 8）**："先单独取出一家公司看清楚，确认结果符合直觉，再推广到全部公司"——真正有教学经验的人才会说这句话。它不是教函数，是教方法论。

- **Cell 139（阶段 8）**："本章数据是年度数据，不适合重点演示 `resample()`"——主动告诉学生什么不学、为什么，这是判断力，也是教材的自信。

- **Cell 77（链式赋值）**："建议优先使用 `df.loc[条件, 列名] = 新值`"——代码块 + 直接的指导性语言，比前面的编号列表有温度得多。

这些段落的问题在于太稀疏。如果在每个阶段至少放置 2–3 处类似的语言——提醒、警告、追问、方法论建议——整章的质感会完全不同。

## 七、总结

| 维度 | 评价 |
|------|------|
| 函数覆盖 | ✅ 完整，核心 API 均有涉及 |
| 概念准确性 | ✅ 无误 |
| 文本可读性 | ✅ 清晰，易于扫读 |
| 教师声音 | ⚠️ 整体缺失，仅 3–4 处例外 |
| 经验细节（坑） | ⚠️ 系统性缺失 |
| 阶段间叙事 | ⚠️ 无衔接，各阶段独立成篇 |
| 范例质感 | ⚠️ 前半具体，后半偏抽象 |

文本的功能几乎全部偏向"信息传递"——告诉学生函数叫什么、参数怎么用。这部分 AI 可以代劳。"经验传递"——告诉学生哪里容易摔、摔了怎么看伤口、下次怎么绕开——才是教材的不可替代性，也是当前版本最薄弱的地方。

**改写方向建议：**

1. 把"编号列表 + 函数签名"模式压缩为辅助形式（保留在小结中作为函数清单即可），概念讲解改用对话式
2. 在每个概念单元后增加至少一处"钉子"：这个操作最常见的犯错方式、报错信息、排查思路
3. 给每个阶段之间加一句过渡语，提示上一阶段的产物和本阶段的关系
4. 将阶段 4、6、7、8 的范例改写为与阶段 1–3 同等的具体程度
5. 把"看一眼"扩展为贯穿全章的习惯性检查点，在每个阶段小结中呼应
