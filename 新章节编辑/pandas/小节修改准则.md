# 小节修改准则

1. 每个阶段按“知识点簇”组织，不按单个函数零散罗列。
2. 新方法、函数、属性第一次出现前，先给出简短说明。
3. 说明采用数字列表，并尽量以方法、属性或写法开头，便于肉眼查询。
4. 同类工具合并说明，例如 `head()` / `tail()` 放在一起。
5. 只有一个方法时，不强行单独编号，尽量并入更大的知识点簇。
6. `import`、`set_option()` 等准备性代码不写正文解释，放代码注释即可。
7. 代码中属于本节知识点的语句，在行末加简短注释。
8. 一个 code cell 尽量只产生一个主要输出。
9. 工作副本要解释为数据分析习惯：拿到原始数据后复制副本，在副本上操作，必要时可以回到原始表重新开始。
10. 阶段末尾的练习提示统一写成：`**练习**：完成最后的阶段 X 练习。`
11. 最后练习区的具体题目保留编号，格式为：`**练习 X.Y**：题目名称`。
